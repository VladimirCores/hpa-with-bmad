1. **Shallow records.** Nine of ten story files are 21–23 line records (story, ACs, Files) without Dev Agent Records, review findings, or baseline commits. Only 2-2 has full depth — so the audit trail is thin exactly where confidence should be documented.
2. **Cross-system drift origin.** Harbor config lives in `gitops/harbor/base/harbor-values.yaml` (v2.11.3 pinned across core/jobservice/registry/trivy/chartmuseum) and installer scripts reference the same facts independently — the systemic fragility that surfaced as Epic 10's harbor drift, patched by 10-2's parsed-equality drift guard.
3. **Unpinned records.** Baseline commit recorded only on 2-2 (`6d71180`); the other nine stories are not pinned to delivery commits.

## Key Insights

1. The "two representations of one fact" pattern (kustomize tree vs installer expectations) starts here in Epic 2; the 10-2 drift guard is the reference fix and should be the template.
2. Deep records (2-2) are the exception, not the norm — review-findings depth should be standard for high-risk GitOps stories, not a one-off.
3. Baseline commits make the audit trail verifiable; without them, done means "claims to be done."
